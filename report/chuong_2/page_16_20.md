## 2.4. Porter's Five Forces and System Requirements

### 2.4.1. Porter's Five Forces analysis for VocalMind

#### 2.4.1.1. Rivalry among existing competitors (High)
The note-taking and AI assistant market is crowded with major players such as Notion, Obsidian, Evernote, and deeply integrated assistants like Apple Intelligence and Google Gemini. These competitors have major advantages in capital, infrastructure, and existing users. VocalMind differentiates itself by focusing entirely on a minimal Voice-First experience combined with deep contextual memory and Vietnamese-language optimization, which global tools have not solved completely.

#### 2.4.1.2. Threat of new entrants (Medium)
The technical barriers to building a basic AI app are dropping thanks to widely available APIs from OpenAI, Google Cloud, and open-source models on Hugging Face. A small development team can quickly build a wrapper app using those APIs. However, optimizing asynchronous audio processing, integrating long-term graph memory like Mem0, and optimizing Vietnamese speech with Vieneu requires deeper technical work and research time, which creates a meaningful barrier for new entrants.

#### 2.4.1.3. Bargaining power of suppliers (Medium to High)
VocalMind depends on GPU infrastructure providers such as AWS, Google Cloud, RunPod, or local providers like VNG Cloud to run ASR, TTS, and LLM models. GPU rental costs fluctuate and tend to rise because of global AI demand. Using commercial LLM APIs also makes the project dependent on provider pricing policies. The risk mitigation strategy is to keep the system cloud-agnostic and eventually self-host smaller open-source models such as Llama 3 8B or Qwen 2.5 7B on private servers once the user base is large enough.

#### 2.4.1.4. Bargaining power of customers (Low to Medium)
Individual users have many note-taking options on the market. If VocalMind does not deliver strong value or is priced too high, customers can leave easily. However, once users build a large "Second Brain" with thousands of tightly connected memories in VocalMind, switching costs become very high. They will not want to lose an assistant that "understands them like a close friend" and start over with a blank tool.

#### 2.4.1.5. Threat of substitutes (Medium)
Substitutes for VocalMind include paper notebooks, the phone’s built-in voice recorder, or the habit of sending voice messages to one-person chat groups on Zalo/Messenger. To beat these substitutes, VocalMind must prove much greater convenience: not just storing raw audio, but automatically classifying, reasoning, and proactively reminding users based on real context.

### 2.4.2. System Requirements

#### 2.4.2.1. Functional requirements
VocalMind must satisfy the following core functional requirements:
1.  **Voice language selection:** Users can choose the main conversation language (Vietnamese or English) on the app's home screen through a clear dropdown menu.
2.  **Voice capture and recording:**
    *   The system allows users to start and stop recording with a single toggle.
    *   The record button must display a pulse animation that matches the audio level or recording state.
    *   Audio files are saved temporarily in an appropriate format (.m4a or .wav), and temporary storage is cleaned up after upload succeeds.
3.  **Speech recognition (ASR):** Convert audio captured from the mobile device into text in the selected language with the highest possible accuracy.
4.  **Smart memory layer:**
    *   Automatically extract entities (people, time, location, events) from the recognized text.
    *   Update the long-term memory of a specific user (`user_id`).
    *   Automatically link new information to old memories to update personal knowledge, such as merging debts from the same person or updating new habits.
5.  **AI response generation:** Based on the current question and related memories retrieved from Mem0, generate a natural, concise, and personalized answer.
6.  **Speech synthesis (TTS):** Convert the LLM response into a natural, high-quality audio file for playback on the user's mobile device.
7.  **Permission management:** Check and request microphone permission on the mobile device. Handle cases where the user denies permission by guiding them to the phone's system settings.

#### 2.4.2.2. Non-functional requirements
1.  **End-to-end latency:** The long-term design goal is to reduce the total time from when the user stops recording to when the app begins speaking back to under **3.0 seconds**. The current test run on an RTX 2080S recorded about **14.22 seconds**, so latency still needs optimization.
2.  **ASR accuracy:** Achieve a Word Error Rate (WER) below **10%** for common Vietnamese speech in low-noise environments.
3.  **Security and privacy:**
    *   Encrypt all data transmitted between Client and Server over HTTPS.
    *   The user's memory database must be clearly separated and protected with authentication.
4.  **Availability:** The Backend API should run reliably with at least **99.5%** uptime.
5.  **State persistence:** The mobile app must remember the previously selected language state even after being fully closed, using `HydratedCubit`.
